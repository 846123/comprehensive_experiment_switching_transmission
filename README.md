# 局域网音视频聊天室
基于Python asyncio TCP实现的多客户端聊天室，支持文本通信、文件传输、音视频通话。两台设备接入同一局域网即可运行。

## 整体实现功能
两台设备，在同一局域网内。一台设备首先运行server端，其次两台设备各自运行client端，在终端命令行进行交互：发送文本、文件和视频通话，可以达到类似聊天室的功能。

其中server端设定为`0.0.0.0:8080`，client端启动时传入server端的IP与端口`8080`；文件发送和接收需要在client同层目录里面，否则需要cd命令切换工作目录；若接收目录存在同名文件，新接收文件会直接覆盖原有文件。

### Server端
基于asyncio搭建异步 TCP 服务器，并发处理多个客户端连接，实现网络数据收发与消息转发；os库用于提取文件名，剥离路径字符串。
1. 接收文件二进制流，并分块转发给其余在线客户端；
2. 接收单帧视频二进制数据，仅转发给当前处于视频通话中的客户端；
3. 接收单段音频二进制数据，仅转发给当前处于音频通话中的客户端；
4. 实现单个客户端连接的核心处理协程；
5. 提供程序入口，创建并启动 TCP 服务。

### Client端
使用asyncio实现异步 TCP 网络通信；sys读取命令行启动参数；os完成文件路径判断与文件名提取；cv2完成摄像头采集、图像编解码与窗口渲染；numpy处理图像矩阵与音频采样数组；threading开辟独立工作线程，处理音视频采集与渲染，防止阻塞asyncio异步事件循环；time提供线程延时；带最大长度限制的deque缓存音视频帧，新帧入队自动丢弃过期旧帧，降低传输延迟；sounddevice完成麦克风音频采集与扬声器音频播放。
1. 独立画面渲染线程，实现本地预览画面与远端接收画面左右分屏显示；
2. 音频播放线程，解码并播放远端收到的音频数据；
3. 音频采集线程，读取本机麦克风音频，封装后发送至服务端；
4. 数据接收协程，持续接收服务端转发数据，完成解析并分发给对应处理逻辑；
5. 视频采集线程，读取本机摄像头画面，本地预览并将图像帧发送至服务端；
6. 音视频通话发起功能；
7. 音视频通话挂断功能；
8. 客户端主协程，建立 TCP 连接，处理控制台用户输入指令；
9. 读取本地文件，分块向服务端发送文件二进制数据。

## 通信流程
### 文本通信
客户端发送文本消息 → 服务端接收文本 → 服务端将文本广播给其余所有在线客户端 → 各客户端接收并打印文本。

### 文件传输
文件发送客户端发送文件元信息与文件二进制流 → 服务端接收并转发数据给其余在线客户端 → 接收客户端接收数据，在本地磁盘重建文件。

### 视频与音频通话
**视频通话**
发起客户端发送通话邀请 → 服务端广播邀请消息 → 接收客户端确认接受通话；双方采集本地视频帧发送至服务端；服务端仅在通话参与者之间转发视频帧；两端客户端接收并渲染远端画面；任意一方发起挂断，服务端广播挂断通知，两端停止视频流收发。

**音频通话**
发起客户端发送通话邀请 → 服务端广播邀请消息 → 接收客户端确认接受通话；双方采集本地音频片段发送至服务端；服务端仅在通话参与者之间转发音频片段；两端客户端接收并播放远端音频；任意一方发起挂断，服务端广播挂断通知，两端停止音频流收发。

## 涉及路由与转换技术
两台物理主机接入同一局域网，通信依靠二层局域网交换、ARP地址解析协议、TCP端口寻址；同网段主机互相通信不经过三层路由转发，也不使用NAT。

数据转换包含：UTF-8文本编解码、JPG图像编解码、PCM音频采样格式转换、自定义应用层协议封装与解析；采用asyncio异步IO模型实现多客户端并发。

## 运行说明
1. 两台电脑接入**同一个局域网**，关闭Windows防火墙或放行8080端口TCP入站规则。
2. 在服务端机器运行服务端：
```powershell
python server.py
```
服务端默认监听 `0.0.0.0:8080`

3. 在客户端机器运行客户端，传入服务端内网IP与端口：
```powershell
python client.py 10.59.9.105 8080
```
> 替换`10.59.9.105`为你服务端电脑真实内网IP。

## 打包方式
使用`pyinstaller`打包为Windows可执行程序。
服务端打包命令：
```powershell
pyinstaller --noconfirm -F --hidden-import=numpy server.py
```
客户端打包命令：
```powershell
pyinstaller --noconfirm -F --hidden-import=numpy --hidden-import=cv2 --hidden-import=sounddevice client.py
```
> 打包后client.exe不能直接双击运行，双击无法传入IP与端口参数，需要在PowerShell终端传入参数启动。

## 实验问题解决与心得
1. 文件发送时，Windows11复制粘贴得到的文件路径自带双引号，程序增加处理逻辑识别带引号路径，提升文件发送操作便捷性。
2. 功能验证阶段：可使用Windows11虚拟机测试文本与文件通信；虚拟机网络采用桥接模式。校园网存在网络限制，桥接模式无法正常使用，手机热点环境可以完成桥接测试。受摄像头硬件独占机制限制，虚拟机无法挂载物理摄像头，不能完成音视频功能验证；物理主机测试时需要确认摄像头正常启用。
3. 音频库选型：最初选用pyaudio，安装需要pipwin工具，且pipwin存在Python版本兼容报错问题，因此改用sounddevice替代。
4. Python程序打包：使用pyinstaller打包程序与依赖库。打包后的client.exe无法直接双击运行，原因是双击启动无法传入服务端IP、端口等命令行参数，需要在程序所在目录打开PowerShell，传入参数启动。
5. Windows防火墙会拦截局域网TCP连接，需要关闭专用网络防火墙或配置入站规则放行8080端口，否则两端无法建立通信。
