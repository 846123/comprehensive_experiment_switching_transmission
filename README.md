## 局域网音视频聊天室
基于 Python asyncio 实现 TCP 信令 + UDP 媒体流的多客户端 GUI 聊天室，支持文本通信、文件传输、多人音视频通话、多人回合制扫雷游戏。两台及以上设备接入同一局域网即可运行。

### 整体实现功能
多台设备接入同一局域网，一台运行服务端，其余运行客户端，通过图形界面交互：可进行文本聊天、文件收发、多人音视频通话，还可邀请全员参与回合制扫雷游戏。
服务端默认监听 `0.0.0.0:8080`（TCP 信令）与 `0.0.0.0:8081`（UDP 媒体中继）；客户端通过 GUI 输入服务端 IP 与昵称即可连接；文件传输支持自定义保存路径，同名文件自动重命名。

#### Server端
基于 asyncio 搭建异步 TCP 服务器，并发处理多个客户端连接；独立 UDP 套接字实现媒体流中继；模块化管理聊天、文件、游戏、通话四大业务。
1.  客户端连接生命周期管理，支持全员广播与定向广播
2.  文本消息接收与全员广播转发
3.  文件传输队列管理，串行流式分片转发
4.  多人扫雷房间管理，完整游戏逻辑与状态同步
5.  多人音视频通话房间管理，邀请、状态同步与成员管理
6.  UDP 媒体流批量中继，仅在通话成员间转发
7.  客户端异常掉线自动清理，业务状态联动回收

#### Client端
基于 PyQt6 实现图形交互界面；独立 QThread 维护 TCP 网络连接；多线程处理音视频采集与播放，避免阻塞 UI；自定义应用层协议解析，信号驱动 UI 更新。
1.  图形化聊天主窗口，气泡式消息展示，自适应宽度
2.  独立 TCP 网络线程，消息解析与 Qt 信号分发
3.  OpenCV 视频采集、JPEG 编码与画面渲染
4.  sounddevice 音频采集与播放，自适应缓冲防抖动
5.  多人音视频通话界面，本地大画面预览 + 远程多窗口展示
6.  麦克风/听筒双状态控制，全员状态实时同步显示
7.  文件传输发送/接收独立进度弹窗，支持自定义保存路径
8.  多人扫雷完整交互：邀请弹窗、游戏棋盘、结算排名
9.  通话与游戏邀请均带 30 秒倒计时，超时自动处理

## 通信流程
### 文本通信
客户端发送文本消息 → 服务端接收文本 → 服务端将文本广播给其余所有在线客户端 → 各客户端接收并以气泡形式展示消息。

### 文件传输
发送端选择文件发起传输 → 服务端接收元信息并入队排队 → 轮到当前文件时向所有接收端广播元信息 → 发送端分片发送数据，服务端流式转发 → 接收端按偏移写入本地文件 → 传输结束发送结束包，两端关闭进度弹窗。

### 音视频通话
发起客户端发送通话邀请 → 服务端全员广播邀请 → 各客户端响应，服务端同步状态 → 满足人数要求后服务端通知通话开始 → 双方采集音视频帧通过 UDP 发送至服务端 → 服务端仅在通话参与者之间批量转发媒体流 → 各客户端接收并渲染画面、播放音频 → 任意成员挂断，服务端同步成员状态，人数不足自动结束通话。

### 多人扫雷
任意玩家发起游戏邀请 → 服务端全员广播邀请 → 各客户端响应，服务端实时同步响应状态 → 满足人数要求后正式开局 → 玩家回合制操作，服务端同步棋盘状态 → 满足结束条件后服务端广播结算结果 → 玩家选择再来一局，满足人数要求开启新一局。

## 涉及路由与转换技术
### 简单介绍
多台物理主机接入同一局域网，TCP 信令与 UDP 媒体流均依靠二层局域网交换、ARP 地址解析、端口寻址；同网段主机通信仅经过二层交换，不触发三层路由与 NAT。
数据转换包含：UTF-8 文本编解码、JPG 图像编解码、PCM 音频采样格式转换、自定义应用层协议封装与解析；采用 asyncio 异步 IO 模型实现多客户端并发。

### 详细说明
项目包含服务端与客户端。客户端应用层生成文本、文件、音视频、游戏指令等二进制数据流，数据沿 OSI 协议栈自上而下逐层封装，最终以比特流交付局域网二层交换机，交换机基于 MAC 地址完成帧转发。
TCP 通道承载所有信令与可靠数据（文本、文件、游戏/通话指令）；UDP 通道承载低延迟音视频媒体流。服务端应用层收到数据后，按业务类型分发给对应模块处理，再对目标客户端独立重新封装报文，经协议栈封装后由交换机转发至目标客户端。
界面渲染仅为应用层本地展示操作；路由与交换的选择由发送主机根据目的 IP 与本机 IP 是否同网段自动判断，同网段仅使用二层交换，跨网段则借助路由器执行三层路由转发，链路内部仍采用二层交换传输数据。

## 运行说明
### 打包前运行
1.  多台电脑接入**同一个局域网**，关闭 Windows 防火墙或放行 8080 端口 TCP、8081 端口 UDP 入站规则。
2.  在服务端机器运行服务端：
```powershell
python -m server.main
```
服务端默认监听 `0.0.0.0:8080`（TCP）与 `0.0.0.0:8081`（UDP）。
3.  在客户端机器运行客户端：
```powershell
python -m client.main
```
在弹出的登录窗口中输入服务端内网 IP 与自定义昵称，点击连接即可进入聊天室。

### 源码状态运行
1.  多台电脑接入**同一个局域网**，关闭 Windows 防火墙或放行 8080 端口 TCP、8081 端口 UDP 入站规则。
2.  在服务端机器双击运行 `局域网聊天室服务端.exe` 启动服务端。
3.  在客户端机器双击运行 `局域网聊天室客户端.exe`，在弹出的登录窗口中输入服务端内网 IP 与自定义昵称，点击连接即可进入聊天室。

## 打包方式
使用 `pyinstaller` 打包为 Windows 可执行程序，入口文件为项目根目录下的 `run_server.py` 与 `run_client.py`。

服务端打包命令：
```powershell
pyinstaller -F -n 局域网聊天室服务端 run_server.py
```

客户端打包命令：
```powershell
pyinstaller -F -n 局域网聊天室服务端 run_client.py
```

## 实验问题解决与心得
### 终端版
1.  文件发送时，Windows11复制粘贴得到的文件路径自带双引号，程序增加处理逻辑识别带引号路径，提升文件发送操作便捷性。
2.  功能验证阶段：可使用Windows11虚拟机测试文本与文件通信；虚拟机网络采用桥接模式。校园网存在网络限制，桥接模式无法正常使用，手机热点环境可以完成桥接测试。受摄像头硬件独占机制限制，虚拟机无法挂载物理摄像头，不能完成音视频功能验证；物理主机测试时需要确认摄像头正常启用。
3.  音频库选型：最初选用pyaudio，安装需要pipwin工具，且pipwin存在Python版本兼容报错问题，因此改用sounddevice替代。
4.  Python程序打包：使用pyinstaller打包程序与依赖库。打包后的client.exe无法直接双击运行，原因是双击启动无法传入服务端IP、端口等命令行参数，需要在程序所在目录打开PowerShell，传入参数启动。
5.  Windows防火墙会拦截局域网TCP连接，需要关闭专用网络防火墙或配置入站规则放行8080端口，否则两端无法建立通信。

### GUI版
1.  传统的server、client两个python文件到开发的中后期会面临上千行代码，卡顿出现，可读性变差。所以重构代码，划分为server和client两个软件包等。
2.  文本通信：想做到拉伸聊天窗口对话信息自适应扩张，失败；聊天信息多到刷屏时，没有自动滚屏功能，遗憾。
3.  对于结构化的目录，创建脚本来进行打包。
